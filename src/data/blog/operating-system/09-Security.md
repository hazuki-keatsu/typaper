## 密码学发展阶段  

### 第一阶段——古典密码  
- 密码学是艺术而非科学，数据安全基于算法保密。  
- 加密方法：替换，手工或机械变换。  
- 代表体制：  
  - 单表替换：Caesar密码  
  - 多表替换：Playfair、Hill、Vigenere  
  - 转轮密码：Enigma  
- **频率分析**：自然语言字母分布不均匀，是替换密码的弱点。

### 第二阶段（1949~1975）  
- 计算机使复杂密码成为可能。  
- **标志性事件**：  
  - 1949年，香农发表《保密系统的信息理论》，密码学成为专门学科。  
  - 1967年，David Kahn的《The Codebreakers》  
  - 1971-73年，Horst Feistel等的技术报告  
- 数据安全基于密钥而非算法保密。  
- **对称加密**：Alice和Bob使用共享密钥K加密通信。

### 第三阶段（1976～）  
- 公钥密码学成为主要方向，实现无密钥传输的保密通信。  
- **代表性事件**：  
  - 1976年，Diffie和Hellman发表《密码学新方向》  
  - 1977年，RSA公钥算法提出  
  - DES算法出现  
  - 80年代：IDEA、CAST  
  - 90年代：Rijndael、RC6，椭圆曲线算法  
  - 2001年，Rijndael成为DES替代者（AES）  

### 公钥密码体制  
- **RSA**：1977年由Rivest, Shamir, Adleman发明，基于大数素因子分解的困难性。  
- **中国现代密码学奠基人：肖国镇**：提出肖-Massey定理，开拓流密码研究新领域。

### 破解者如何攻破认证

LBL实验室被破解：

这是一起被后世视为计算机间谍案开端的著名网络安全事件，由美国劳伦斯伯克利国家实验室的系统管理员克里夫·斯托尔（Clifford Stoll）所发现并追踪破获。在1986年，斯托尔在审计实验室计算机系统账单时发现了一笔0.75美元的账目误差，顺藤摸瓜后发现一名黑客已非法入侵实验室系统，其真实意图并非恶作剧，而是利用LBL作为跳板，攻击美国军事和国防承包商的计算机网络。与当时通常“堵截”的做法不同，斯托尔大胆选择“放虎归山”，继续允许黑客访问以监控其所有活动。在长达10个月的追踪中，他发现这名黑客先后攻击了约450台计算机，并成功侵入其中30多台，目标直指“核武器”、“战略防御计划”、“生物武器”等绝密关键词。最终，斯托尔通过精心设置的虚假诱饵追踪到信号源位于西德的汉诺威，协助FBI和德国警方抓获了受雇于克格勃（KGB）的黑客马库斯·赫斯（Markus Hess）等人。整个故事后来被斯托尔写成了畅销书《The Cuckoo‘s Egg》，成为全球信息安全领域的经典教材。

## 内部攻击（Attacks from Inside the System）  

### 后门（Backdoor）
后门是隐藏在程序中的一个功能或命令，允许用户执行一些通常不允许执行的操作。

按正常方式使用时，程序可以完全按预期执行。然而，如果启用了隐藏功能，程序会执行通常违反安全策略的意外操作，比如进行权限升级。

很好的例子：彩蛋

### 特洛伊木马（Trojan Horses）  
- 免费程序包含有害代码  
- 替换受害者的实用程序，诱使用户运行  

### 登录欺骗（Login Spoofing）  
对应用的登录界面进行高仿，以诱导用户输入自己的账号和密码。常见于各种网页。

### 逻辑炸弹（Logic Bombs）
程序员编写潜在的破坏程序，每日输入密码避免爆炸；若被解雇，炸弹引爆。常见于对付老板不愿意结工钱的场景，例如定时锁。

### 通用安全攻击（**Generic Security Attacks**）
- 请求内存、磁盘空间并直接读取
- 尝试非法系统调用
- 启动登录并按下DEL、RUBOUT、BREAK
- 尝试修改复杂OS结构
- 说服系统程序员添加后门
- 请求管理员秘书帮助“忘记密码”的用户

### 安全设计原则（Design Principles for Security）  
- 系统设计应公开  
- 默认无访问权限  
- 检查当前权限  
- 为每个进程分配最小权限  
- 保护机制应简单、统一、位于系统最底层  
- 方案应心理可接受  
- 保持简洁

## 保护机制（Protection Mechanisms）  

### 保护领域（Protection Domains）

**核心概念**：保护领域是一个 **(对象, 权限)** 对的集合，规定了在该领域中运行的进程可以对哪些资源执行哪些操作。每个对象（文件、设备、进程等）在不同领域中可能有不同的访问权限。

![image-20260521165818129](/images/operating-system/image-20260521165818129.png)

**UNIX 中的体现**：UNIX 的保护域由 (UID, GID) 决定。同一个进程在不同时刻可以处于不同保护域：

- 普通用户执行程序时，进程运行在该用户的域中；
- 当程序设置了 **setuid** 位（如 `passwd`），执行时进程临时切换到文件所有者（通常是 root）的域，从而获得修改 `/etc/passwd` 的权限；
- 执行完毕，进程退出特权域。

**保护矩阵**：将所有保护域和所有对象画成一张矩阵表，行是域，列是对象，单元格填写该域对该对象的权限：

|        | File1 | File2 | File3 | Printer |
|--------|-------|-------|-------|---------|
| 领域1  | RW    | R     | —     | W       |
| 领域2  | R     | RW    | —     | —       |
| 领域3  | —     | —     | RWX   | W       |

这个矩阵在实际系统中**大且稀疏**——大多数单元格为空，因此不会真的按矩阵存储，而是按行（权能表）或按列（访问控制表）分别实现。

### 访问控制表（Access Control Lists，ACL）

**核心思想**：把保护矩阵**按列**存储，每个对象（文件）附带一张表，列出哪些域（用户/进程）可以对该对象执行什么操作，即"谁有权限来访问我"。

**UNIX ACL 示例**：

```plaintext
文件 report.txt 的 ACL:
  UID=alice: RWX    ← alice 可读写执行
  UID=bob:   RW-    ← bob 可读写，不能执行
  GID=staff: R--    ← staff 组所有成员只读
  Other:     ---    ← 其他人无任何权限
```

每个文件维护自己的 ACL，当进程尝试访问文件时，系统遍历 ACL 找到匹配该进程身份（UID/GID）的条目，检查请求的操作是否被允许。

**优点**：

- 直观：权限和对象绑定，符合"文件属于谁、谁能看"的自然思维
- 集中管理：修改一个文件的权限只需改它的 ACL

**缺点**：
- 若一个用户属于多个组，ACL 可能有多条匹配，需要规定优先级
- 粒度有限：UNIX 传统 ACL（rwx）只有三种权限位，无法表达"允许追加但不能覆盖"这种细粒度控制。现代系统（如 Windows NTFS、Linux ACL 的 `setfacl`）支持更丰富的权限掩码

### 权能字（Capabilities）

**核心思想**：把保护矩阵**按行**存储，每个进程持有一张权能列表（C-list），列出该进程可以对哪些对象执行什么操作，即"我能访问哪些东西"。

**权能字**本质上是一个不可伪造的令牌——进程出示权能字来证明自己对某对象有某权限。每个权能字包含：

- 对象标识符（如 i-node 号、文件描述符）
- 权限字段（如 R、W、X 等）

**UNIX 中的影子**：文件描述符就是权能字的一种朴素实现，打开文件后获得的 fd 本质上是一个对该文件执行某操作的令牌。但文件描述符在进程 fork 时会被子进程继承，不够精细。

**防止用户篡改的方法**（权能字必须不可伪造，否则用户可以随意给自己加权限）：

- **标记架构**：每个内存字附一个额外的标签位，硬件区分该字是数据还是权能字。普通指令只能读数据；权能字只能由操作系统内核操作，用户进程无法直接修改标签位或伪造权能字。PSW（程序状态字）中也有标记位控制代码执行权限。这种方式安全性高但需要特殊硬件支持。

- **将权能字保留在 OS 内核空间**：进程的权能列表不在用户地址空间中，只有通过系统调用才能间接操作，内核检查后决定是否授予。用户永远拿不到权能字的裸数据，自然无法伪造。

- **用户空间管理但加密保护**：进程可以持有加密后的权能字在用户空间，但无法解密或修改，密钥由内核保管。进程每次使用权能字时需传递回内核，内核解密后验证其真实性。

**ACL vs 权能字 对比**：

|         | ACL                        | 权能字                       |
|---------|----------------------------|------------------------------|
| 视角     | 每个对象：谁可以访问我？    | 每个进程：我能访问什么？      |
| 存储方式 | 随对象存储                  | 随进程存储                    |
| 类比     | 门上的名单（看名字放人）    | 钥匙串（持钥匙才能开门）      |
| 权限检查 | 查表匹配身份                | 出示令牌验证                  |
| 撤销难度 | 直接删表项，立即生效        | 进程可能已复制令牌，收回困难  |
| 优点     | 直观，撤销方便              | 灵活，便于委托/传递           |
| 缺点     | 粒度有限                    | 令牌到处复制后难以回收        |

### 多级安全（Multilevel Security）  
- **自主访问控制（Discretionary Access Control）**：用户决定谁读写文件  

- **强制访问控制（Mandatory Access Control）**：系统强制执行安全策略  

- **Bell-La Padula模型**：  

  - 简单安全属性：进程只能读同级或更低级对象  
  - *属性：进程只能写同级或更高级对象  
  - 缺点：保证机密性，不保证完整性  

  ![image-20260521182002270](/images/operating-system/image-20260521182002270.png)

- **Biba模型**：  

  - 简单完整性原则：进程只能写同级或更低级对象  
  - 完整性*属性：进程只能读同级或更高级对象

### 隐蔽信道（Covert Channels）

隐蔽信道是指并非为通信目的而设计，但被恶意利用来传输信息的间接通道。它的核心特征是借路通信——利用系统中原本用于其他目的的共享资源，在进程之间传递数据，从而绕过了系统的正式安全策略。

#### 为什么隐蔽信道是安全威胁？

在多级安全系统，即便 Bell-La Padula 模型严格禁止高安全级进程向低安全级进程写数据，隐蔽信道可以让高安全级进程和低安全级进程通过某个共享资源的状态变化来传递信息，从而实现"不能直接写，但可以打暗号"的数据泄露。

#### 两种类型

- **存储信道**：发送方通过修改某个共享存储资源的状态（如文件名、磁盘空间使用量、文件锁状态等）来编码信息，接收方通过读取该资源的状态变化来解码。
- **时间信道**：发送方通过控制自己对某个资源的使用时机（如 CPU 占用时长、磁盘寻道模式等）来编码信息，接收方通过观测自己操作的响应时间变化来解码。

#### 图像隐写

通用的隐蔽信道技术，不仅限于操作系统层面。数字图像每个像素的 RGB 值的最低有效位（LSB，Least Significant Bit）对肉眼几乎不可见于是可以将秘密消息的比特替换到图像每个像素的最低位中。

#### 隐蔽信道为何难以防御？

- **检测困难**：系统中有成百上千个共享资源都可能被用作信道（磁盘空间、文件锁、进程 ID、错误返回值、响应时间等），无法全部封堵。
- **清除困难**：即使知道存在某个隐蔽信道，彻底消除它可能要求削减系统的正常功能或显著降低性能。
- **带宽可能很低但不等于无害**：哪怕每小时只渗漏几个比特，对于一个能长期运行的木马而言，足够偷走密钥或关键情报。

## 操作系统安全（OS Security）  

### 引导顺序（Boot Sequence）及安全  
从关机状态到将操作系统加载到内存的操作称为引导。当按下计算机的启动按钮后，它首先执行的存储在**基本输入/输出系统**(BIOS)固件组件中的代码。BIOS将第二阶段的引导加载程序加载到内存，该程序会将操作系统其余部分加载到内存，然后将控制权交给操作系统。 

恶意用户可以利用引导过程的一些**脆弱点**来通过控制计算机的执行。

可以通过设置BIOS密码来防止恶意用户引导第二阶段的加载程序

###  引导设备的层次（Boot device hierarchy）

第二阶段引导程序允许用户指定应该使用哪个设备来加载操作系统。默认选项是从硬盘驱动器引导；也可能从外部介质如DVD驱动器或者引导U盘引导

从安全角度考虑，应该确保操作系统是从值得信任的介质启动。

BIOS系统会提供一个引导的层次结构，它可以决定引导设备的优先级。攻击者可以绕过运行的计算机上的安全机制，从外部介质引导其他的操作系统来访问硬盘

防止这类攻击的有效措施：**对第二阶段引导程序的启动设置了密码保护，只允许授权用户从外部存储介质引导计算机启动**。

### 休眠（Hibernation）  
现代计算机系统都有进入电源关闭状态的功能，这种状态称为休眠。当进入休眠时，操作系统将计算机内存的全部内容都存储到磁盘的休眠文件中；当系统通电后，可以迅速恢复计算机状态

**安全隐患**：如果没有安全防范措施，攻击者可以利用休眠，入侵计算机

例如，内存的全部内容都保存在休眠文件中，攻击者可以从休眠文件中获取一些敏感信息。Windows系统的休眠文件为C:\hiberfil.sys。攻击者还有可能会修改hiberfil.sys文件，当计算机再次启动时改变在计算机上执行的程序。Windows系统不会删除休眠文件，计算机重启后该文件依然存在。

**防御措施**：使用硬盘加密来保护休眠文件

### 监控、管理和日志（Monitoring, Management, and Logging）  
**事态感知**：记录那些进程正在运行、哪些计算机在联网；如果操作系统遇到任何意外或者可疑操作，都会留下重要线索。通过留下的线索，可以解决常见的问题，还能确定出现安全漏洞的原因。

操作系统为了监控和记录提供的主要手段：事件日志和进程查看器。

**事件日志**

操作系统有内置功能来管理事件日志。日志项一般都包含时间戳和对时间的描述。

- Windows系统定义了三种日志源：系统、应用程序和安全。系统日志只有操作系统才能写入；应用程序只能写应用程序日志；而安全日志由操作系统提供的本地安全授权子系统(LSASS)服务才能写入。
- Linux系统的具体日志机制跟发布的版本有关。通常情况下，日志文件存储在`/var/log`中，是具有描述性名称的简单文本文件。如`auth.log`包含用户身份验证记录；`kern.log`记录内核操作等。通常情况下只有特殊的`syslog`守护进程才能写这些日志文件。

### 内存与文件系统安全（Memory and File System Security）  
Windows系统中，虚拟内存页面存储在C:\pagefile.sys中。

Linux系统需用户自己设定一个硬盘分区作为交换分区，存储内存页面。

关闭计算机时，硬盘上的虚拟内存页面会被删除。

**虚拟内存安全问题**：如果攻击者突然将计算机断电，没有正常关闭计算机，此时虚拟内存页面可能未被删除。攻击者通过外部介质引导另一个操作系统，能够查看这些文件并重建部分内存，导致信息泄露。

**解决办法**：对硬盘内容进行加密。
