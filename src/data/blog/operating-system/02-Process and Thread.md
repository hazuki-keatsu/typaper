## 2.1 进程（Processes）

### 进程模型
- **进程**：正在执行的程序，包括程序计数器、寄存器、变量等当前值。

- **多道程序**：内存中同时存在多个程序，但任意时刻只有一个程序在CPU上执行。

- **进程组成**：
  - **代码段**：存放程序的可执行机器指令，通常是只读的，避免进程意外修改自身指令，同时多个进程共享同一段代码。
  
  - **数据段**：用于存放全局变量和静态变量，通常分为已初始化数据段（.data，存放已初始化的全局变量和静态变量）和未初始化数据段（.bss，存放未初始化的全局变量和静态变量，程序加载时，系统会将这片区域清零）
  
  - **堆**：用于动态内存分配，地址从低向高增长（通常高于数据段）；由程序员手动管理，若忘记释放则可能导致**内存泄漏**。
  
  - **栈**：存放函数调用信息，包括函数的参数、局部变量、函数返回地址和保存的寄存器状态（上下文）。特点是地址从高向低增长；由编译器自动分配和释放；每个线程有自己独立的栈。
  
  - **进程控制块（PCB, Process Control Block）**：不是内存中的代码或数据，而是操作系统内核为每个进程维护的一个**数据结构**，记录进程的运行状态和资源信息。
    - **进程标识符**（PID）
    - **进程状态**（就绪、运行、阻塞等）
    - **程序计数器**（PC，下一条指令地址）
    - **CPU寄存器**（上下文切换时保存）
    - **内存管理信息**（页表基址、段界限等）
    - **打开文件表**（已打开的文件描述符）
    - **信号掩码/处理信息**
    - **优先级、记账信息**等
    
    ![image-20260517105305402](/images/operating-system/image-20260517105305402.png)


### 进程创建
- **创建事件**：
  - 系统初始化
  - 系统调用（如 `fork`）
  - 用户请求创建新进程
  - 批处理作业初始化
- **进程树**：父进程创建子进程，子进程可再创建后代，形成树状结构。
- **UNIX 示例**：
  - `fork()`：创建子进程，复制父进程地址空间
  - `execve()`：在子进程中加载新程序

### 进程终止
- **终止条件**：
  - 正常退出（`Normal exit (Voluntary)`）
  - 错误退出（`Error exit (Voluntary)`）
  - 致命错误（`Fatal erro (Involuntary)`）
  - 被其他进程杀死（`(Involuntary)`）
- **级联终止**：父进程终止时，操作系统可能自动终止其所有子进程。

### 进程状态
- **五状态模型**：
  - **新建（new）**：正在创建
  - **就绪（ready）**：等待分配CPU
  - **运行（running）**：正在执行
  - **阻塞（waiting/blocked）**：等待某个事件（如I/O）
  - **终止（terminated）**：执行结束

### 进程间切换

- 时钟中断
- I/O中断
- 由用户程序触发的操作系统用户态与内核态的切换（Trap）
- 内存缺页
- 管理程序的调用（Supervisor call）

<img src="/images/operating-system/image-20260517104800384.png" alt="image-20260517104800384" style="zoom:50%;" />

### 上下文切换

- **定义**：CPU从一个进程切换到另一个进程时，保存当前进程的状态（PCB），恢复下一个进程的状态。
- **开销**：纯额外负担，不执行有用工作。

### 进程调度队列
- **作业队列**：系统中所有进程
- **就绪队列**：内存中准备好运行的进程
- **设备队列**：等待某个I/O设备的进程

## 2.2 线程（Threads）

### 线程模型
- **线程**：轻量级进程，是CPU调度的基本单位。
- **共享资源**：同一进程内的线程共享代码段、数据段、操作系统资源（如打开的文件）。
- **私有资源**：每个线程拥有自己的程序计数器、寄存器集、栈。
- **优点**：
  - 创建和销毁开销小
  - 线程间切换比进程间切换快
  - 适合并行计算和I/O重叠操作
  - 在多CPU系统中实现真正并行

## 2.3 调度（Scheduling）

### 何时触发调度

- 一个新的进程创建
- 一个进程退出
- 一个被I/O或者信号量阻断

### 调度算法的目标

- 所有系统通用目标
  - **公平性（Fairness）**：为每个进程分配公平的CPU时间份额
  - **策略执行（Policy enforcement）**：确保既定的调度策略能够被落实
  - **平衡性（Balance）**：让系统的所有部分都保持工作状态
- 批处理系统（Batch systems）
  - **吞吐量（Throughput）**：最大化每小时完成的作业数量
  - **周转时间（Turnaround time）**：最小化作业从提交到完成的时间间隔
  - **CPU利用率（CPU utilization）**：让CPU始终处于忙碌状态
- 交互式系统（Interactive systems）
  - **响应时间（Response time）**：快速响应用户请求
  - **比例性（Proportionality）**：满足用户对响应速度的预期
- 实时系统（Real-time systems）
  - **满足截止时间（Meeting deadlines）**：避免因超时导致数据丢失
  - **可预测性（Predictability）**：避免多媒体系统中出现的质量下降问题

### 常见调度算法详解

#### 在批处理系统中的调度算法

| 算法                  | 描述                                     | 优缺点                               |
| --------------------- | ---------------------------------------- | ------------------------------------ |
| **FCFS (First-come first-served)**             | 先来先服务                               | 简单，但是CPU利用率较低              |
| **SJF (Shortest job first)**    | 执行最短CPU突发的进程                    | 最小平均等待时间，但需要预知突发时间 |
| **SRTF (Shortest remaining time first)** | 剩余时间最短的优先                       | 最优平均等待时间                     |

#### 在交互系统中的调度算法

| 算法 | 描述 | 优缺点 |
| :--- | :--- | :--- |
| **RR (Round Robin)** | 循环轮转 | 如果时间片设置得比平均CPU突发时间长，抢占将很少发生。但频繁的上下文切换会消耗较多时间。 |
| **Priority scheduling** | 优先调度 | 每个进程被分配一个优先级，优先级高的先执行。但如果所有进程优先级都最高，算法会退化为先来先服务；低优先级进程可能产生饥饿。 |
| **Shortest process next** | 最短作业优先 | 总是产生最小的平均周转时间。问题在于如何确定当前可运行进程中最短的那个，一种方法是根据过去的行为进行估算，并运行估计运行时间最短的进程。 |
| **Multiple queues** | 多级队列 | 将进程按类型（如前台/后台）分配到不同队列，每个队列有自己的调度算法。队列间通常采用固定优先级抢占。**优点**：隔离不同类型任务，灵活配置。**缺点**：队列间可能导致低优先级队列饥饿；配置复杂。 |
| **Guaranteed scheduling** | 保证调度 | 系统承诺每个进程获得一定比例的CPU时间（如1/n）。通过跟踪每个进程实际获得的CPU时间与应获得时间的差值，调度时优先选择差距最大的进程。**优点**：提供绝对公平性，避免进程饥饿。**缺点**：需要实时记账和计算，增加系统开销。 |
| **Lottery scheduling** | 彩票调度 | 每个进程分配若干“彩票”，每次调度时随机抽取一张彩票，持有该彩票的进程获得CPU。优先级可通过分配彩票数量来调节。**优点**：实现简单，可避免饥饿，响应性好。**缺点**：随机性导致短期不公平；需要高质量的随机数生成。 |
| **Fair-share scheduling** | 公平分享调度 | 以用户或组为单位分配CPU份额，而不是以进程为单位。即使某个用户创建了大量进程，也只能获得其用户层级所分配的份额。**优点**：保证用户间的资源公平，防止单一用户过度占用。**缺点**：实现复杂，需要跟踪每个用户的资源使用情况，且可能降低单个进程的响应速度。 |

#### 在实时系统中的调度算法

给定 $m$ 个周期事件，事件 $i$ 在周期 $P_i$ 内发生，并且每个事件需要 $C_i$ 秒的 CPU 时间来处理
那么只有当负载满足以下条件时才能处理：

$$\sum\limits_{i=1}^{m}\dfrac{C_i}{P_i} \leq 1$$

符合此条件的实时系统称为**可调度的**。

### 调度时机

- 进程从运行→等待（I/O、信号量等）
- 进程从运行→就绪（时间片用完）
- 进程从等待→就绪（I/O完成）
- 进程终止

### 调度与分派器
- **分派器（Dispatcher）**：负责上下文切换、切换到用户态、跳转到用户程序适当位置。
- **分派延迟**：停止一个进程并启动另一个所需时间。

### 调度评判标准

- CPU 利用率——让 CPU 尽可能忙碌（Max）
- 吞吐量——每时间单元完成执行的进程数量（Max）
- 周转时间——从提交到完成的间隔（Min）
- 等待时间——进程在准备队列中等待的时间（Min）
- 响应时间——从请求提交到首次响应产生所需时间，而非输出（分时环境下）（Min）

### 各类调度算法详解

1. 先来先服务（FCFS）

   - 按到达顺序调度，非抢占。
   - 缺点是可能导致**护送效应**（短进程被长进程阻塞）。
2. 短作业优先（SJF）

   - 选择下一个CPU执行时间最短的进程。
   - **两种模式**：
     - **非抢占式**：一旦获得CPU，运行至完成。
     - **抢占式**（最短剩余时间优先，SRTF）：新进程的剩余时间更短时可抢占当前进程。
   - **最优性**：SJF在平均等待时间上理论最优。
3. 优先级调度
   - 每个进程有优先级（整数），优先级最高的先运行。
   - 可以是抢占式或非抢占式。
   - SJF是优先级调度的一种特例。
   - **问题**：低优先级进程可能**饥饿**。
   - **解决方案**是**老化**（Aging）随时间推移提高进程优先级。
4. 时间片轮转（Round Robin，RR）
   - 每个进程运行一个固定的**时间片**（通常10-100ms），然后放回就绪队列末尾。
   - 时间片过长 → 退化为FCFS；过短 → 上下文切换开销过大。
5. 多级队列调度
   - 就绪队列划分为多个独立队列。
6. 多级反馈队列
   - 进程可在不同队列之间移动，支持**老化**。
7. 传统UNIX调度
   - 采用**多级反馈队列 + 时间片轮转**。
   - 优先级每秒重新计算一次。
   - 优先级公式：
     - $$cpu[j](i)=\dfrac{cpu[j](i-1)}{2}$$
     - $$p[j](i)=Base[j]+\dfrac{cpu[j](i)}{2}+nice[j]$$
   - 优先级分为多个固定区间，根据进程类型、执行历史和nice值决定。
