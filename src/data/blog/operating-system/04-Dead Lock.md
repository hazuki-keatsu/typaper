## 一、资源的基本概念

### 1. 资源类型
- **可抢占资源**（如内存）：可被系统强制收回，不影响进程。
- **不可抢占资源**（如CD刻录机）：强制收回会导致进程失败。

### 2. 资源使用流程
- 请求资源 → 使用资源 → 释放资源  
- 若请求被拒绝，进程可阻塞或返回错误码。

---

## 二、死锁的定义与必要条件

### 1. 形式化定义
一组进程中的每个进程都在等待一个**只能由该组中其他进程引发的事件**（通常是释放资源），导致所有进程无法运行、释放资源或被唤醒。

### 2. 四个必要条件（必须同时满足）
| 条件           | 说明                                                   |
| -------------- | ------------------------------------------------------ |
| **互斥**       | 资源一次只能分配给一个进程                             |
| **持有并等待** | 进程持有资源的同时可请求新资源                         |
| **不可抢占**   | 已分配的资源不能被强制夺走                             |
| **循环等待**   | 存在一个进程等待链，每个进程等待下一个进程所持有的资源 |

## 四、处理死锁的四种策略

### 1. 鸵鸟算法（Ostrich Algorithm）
- 假装死锁不会发生，不做任何处理。
- 适用场景：死锁极少发生，且预防/恢复成本高。
- Unix、Windows 等通用操作系统采用此方法。

### 2. 死锁检测与恢复
#### 检测
- **单资源类型**：检测资源分配图中是否存在环。
- **多资源类型**：使用矩阵（现有资源、已分配资源、请求资源、可用资源）和算法检测。

#### 恢复方法
| 方法         | 说明                                       |
| ------------ | ------------------------------------------ |
| **抢占**     | 强行从某进程中取走资源（依赖资源性质）     |
| **回滚**     | 将进程回滚到之前保存的检查点（checkpoint） |
| **杀死进程** | 最粗暴但简单，杀死环中一个进程，释放其资源 |

### 3. 死锁避免（Deadlock Avoidance）
- 核心思想：系统始终处于**安全状态**，避免进入不安全状态。
- 安全状态：存在一种资源分配顺序，使得所有进程都能完成。

#### 银行家算法（Banker’s Algorithm）
- **单资源版本**：通过比较当前可用资源与进程最大需求，判断分配是否安全。
- **多资源版本**：
  - 维护矩阵：`E`（资源总数）、`P`（已占有）、`A`（可用）
  - 每次分配前检查是否会导致不安全状态。

### 4. 死锁预防（Deadlock Prevention）
破坏四个必要条件之一：

| 条件           | 预防方法                                                 | 局限性                               |
| -------------- | -------------------------------------------------------- | ------------------------------------ |
| **互斥**       | 使用**假脱机**技术（如打印机守护进程）                   | 不是所有资源都可假脱机（如进程表）   |
| **持有并等待** | 进程在开始前一次性请求所有资源；或释放已有资源后重新请求 | 可能不知道未来所需资源；浪费资源     |
| **不可抢占**   | 允许抢占                                                 | 对许多资源不可行（如打印机中途抢占） |
| **循环等待**   | 对所有资源进行**全局编号**，要求进程只能按序请求资源     | 需要编程规范，有时不灵活             |

## 五、其他相关问题

### 1. 两阶段锁（Two-Phase Locking）
- **阶段一**：尝试锁定所有需要的资源，若发现已被锁则释放所有锁并重新开始。
- **阶段二**：成功获得所有锁后，执行更新并释放锁。
- 适用场景：可重启的程序，不适用于实时系统或过程控制系统。

### 2. 非资源死锁
- 两个进程相互等待对方完成某个任务（如信号量操作顺序错误）也可能导致死锁。

### 3. 饥饿（Starvation）
- 一种资源分配策略（如最短作业优先）可能导致长作业无限期等待。
- 解决方案：先来先服务（FCFS）。
