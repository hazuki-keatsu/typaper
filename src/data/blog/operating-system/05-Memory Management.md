## 一、内存管理概述

- **理想内存特性**：大容量、快速、非易失性。
- **内存层次结构**：高速缓存（小、贵、快）→ 主存（中等速度、价格）→ 磁盘（慢、廉价、大容量）。
- **内存管理器**：负责管理内存层次结构，协调主存与磁盘之间的数据移动。

## 二、基本内存管理

### 1. 无交换或无分页的单道程序
- 早期大型机、小型机、掌上电脑、嵌入式系统、MS-DOS（使用ROM中的BIOS）中使用。

- 内存组织方式：
  - (a) OS + 一个用户进程
  - (b) 部分系统在ROM中
  - (c) 典型MS-DOS布局
  
  ![image-20260518142016532](/images/operating-system/image-20260518142016532.png)

### 2. 固定分区的多道程序
- 将内存划分为多个固定大小的分区，每个分区可运行一个进程。

- 队列组织方式：
  - 每个分区独立队列
  - 单一输入队列
  
  ![image-20260518142103942](/images/operating-system/image-20260518142103942.png)

### 3. 多道程序设计性能分析
- CPU利用率随内存中进程数量增加而提高，但边际效益递减。
- 示例：32MB内存，OS占16MB，每个用户程序4MB，最多4个程序，80% I/O等待时，CPU利用率 = 1 - 0.8^4 ≈ 60%。

### 4. 重定位与保护
- 由于程序加载位置不确定，需要使用**基址寄存器和界限寄存器**进行动态地址映射和保护。

- 物理地址 = 虚拟地址 + 基址；若地址 >= 界限，则产生错误。

  ![image-20260518142732436](/images/operating-system/image-20260518142732436.png)

## 三、交换（Swapping）

- 当主存不足以容纳所有活跃进程时，将整个进程换入换出到磁盘。

- 内存分配随着进程进出而变化，产生空洞（hole）。

- **内存紧凑（memory compaction）**：移动进程以合并空闲空间。

- 使用位图和链表在信息上是等价的

### 用来分配内存的算法

| 算法名称  | 描述                                                         | 优点                                                  | 缺点                                                         |
| --------- | ------------------------------------------------------------ | ----------------------------------------------------- | ------------------------------------------------------------ |
| First fit | 从内存起始位置开始扫描，选择第一个大小足够容纳进程的空闲分区。 | 实现简单，扫描开销小，分配速度快。                    | 容易在内存低地址区域产生大量外部碎片。                       |
| Next fit  | 从上次分配结束的位置开始扫描，选择第一个足够大的空闲分区。   | 相比 First fit 更均匀地使用内存，减少低地址碎片。     | 可能降低分配速度（需维护当前位置），整体性能通常弱于 First fit。 |
| Best fit  | 扫描所有空闲分区，选择大小最接近进程需求（且足够大）的分区。 | 理论上能最小化浪费，减少大块分区被拆分。              | 扫描开销大，容易产生大量难以利用的微小碎片。                 |
| Worst fit | 选择最大的空闲分区进行分配，剩余部分仍为较大的空闲分区。     | 避免产生过多小碎片，剩余分区仍可能被大进程使用。      | 分配效率低（需扫描全部），实际性能不如 Best fit，已较少使用。 |
| Quick fit | 预先维护多个常见大小的空闲块链表（如 4KB、8KB 等），分配时直接匹配。 | 分配速度极快（O(1) 级别），适合频繁分配固定大小对象。 | 需要额外维护链表，合并与回收复杂，容易产生内部碎片和外部碎片。 |

## 四、虚拟内存

- **基本思想**：程序、数据、栈的总大小可以超过物理内存，OS将当前使用的部分放在内存中，其余放在磁盘上。

- **分页（Paging）**：
  - 虚拟地址空间划分为**页（page）**，物理内存划分为**页框（page frame）**。
  
  - **MMU（内存管理单元）** 负责将虚拟地址映射到物理地址。
  
    ![image-20260518144011459](/images/operating-system/image-20260518144011459.png)
  
  - 示例：地址转换过程（如MOVE REG, 8196 → 物理地址24580）。

### 1. 页表（Page Table）
- 记录虚拟页到物理页框的映射。

  <div style="display: flex"><img src="/images/operating-system/image-20260518144032518.png" alt="image-20260518144032518" style="zoom:35%;" align=left /><img src="/images/operating-system/image-20260518144343329.png" alt="image-20260518144343329" style="zoom:50%;" /></div>

- 问题：
  - 页表可能非常大（如32位地址，4KB页，需2^20个条目）。
  - 映射必须快速。
  
- 解决方案：
  - 使用硬件寄存器数组（快但贵）。
  - 页表放在主存中（慢，需多次访存）。

### 2. 多级页表
- 32位地址可划分为：页目录（PT1）、页表（PT2）、页内偏移。
- 示例：0x00403004 → PT1=1, PT2=3, Offset=4，映射到物理地址4206592~4210687。

  <img src="/images/operating-system/image-20260518144511839.png" alt="image-20260518144511839" style="zoom:50%;" />


### 3. 页表项（PTE, Page Table Entry）字段
- **页框号**(Page frame number)：物理页框地址。
- **存在位**(Present/absent)：页面是否在内存中。
- **保护位**(Protection)：读/写/执行权限。
- **修改位（脏位）**(Modified)：页面是否被写过。
- **引用位**(Referenced)：页面是否被访问过。
- **缓存禁用**(Caching disabled)：用于映射设备寄存器。

![image-20260518144754461](/images/operating-system/image-20260518144754461.png)

### 4. 转换检测缓冲区（TLB, Translation Lookaside Buffers）
#### 1) 为什么需要TLB？

现代操作系统使用**虚拟内存**。程序看到的地址是**虚拟地址**，CPU 最终需要访问的物理内存地址是**物理地址**。这个转换通常通过**页表**（Page Table）完成。页表保存在主存中，由操作系统为每个进程维护。

但是如果每次访存都要访问一次主存中的页表，那么一次内存访问就会变成**两次物理访存**（先查页表得到物理地址，再访问目标数据），性能降低 50% 以上。

**TLB** 是 CPU 内部的一个**硬件高速缓存**，专门用来缓存最近使用过的“虚拟页号 → 物理页框号”的映射关系，以及访问权限等属性。它使大多数地址转换无需访问主存中的页表。

### 5. 倒排页表（Inverted Page Table）

传统页表为每个虚拟页维护一个页表项，对于 64 位地址空间（如 2^64），页表将变得极其庞大，无法全部放入内存。倒排页表逆转了这一思路。

#### 基本原理
- 倒排页表只维护**物理页框**对应的条目，而不是虚拟页。
- 整个系统只有一个全局的倒排页表，每个条目对应一个物理页框，记录**哪个进程的哪个虚拟页**正在使用该页框。
- 条目数 = 物理页框数（远小于虚拟页数），大大减少了页表占用的内存。

#### 页表项内容
- **进程ID（PID）**：拥有该页框的进程标识。
- **虚拟页号（Virtual Page Number）**：映射到该页框的虚拟页。
- **保护位**：读/写/执行权限。
- **修改位（脏位）**：页面是否被修改过。
- **引用位**：页面是否被访问过。
- **哈希链指针**：用于解决哈希冲突，指向下一个具有相同哈希值的条目。

#### 地址转换过程
1. CPU 发出虚拟地址 `(pid, v, offset)`。
2. 系统将 `(pid, v)` 通过哈希函数映射到一个哈希值 `h`。
3. 在倒排页表中查找哈希桶 `h` 中的条目，比较 `pid` 和虚拟页号 `v`。
4. 如果匹配，该条目的索引即为物理页框号 `p`；物理地址 = `p × 页大小 + offset`。
5. 如果不匹配，沿哈希链继续查找，直到找到匹配项或遍历完所有条目（缺页）。

#### 优缺点

| 特点 | 说明 |
|------|------|
| **优点** | 页表大小与物理内存大小成正比，而非虚拟地址空间大小；显著节省内存，适合 64 位系统。 |
| **缺点** | 地址转换需要遍历哈希链，查找速度慢于传统页表；无法直接支持共享内存（一个物理页可能被多个虚拟页映射）；通常需要配合 TLB 使用以加速常见情况。 |

## 五、页面置换算法

当发生**缺页（page fault）**时，操作系统需选择一个页面换出，为即将调入的页面腾出空间。不同的置换算法在**缺页率**、**实现开销**和**公平性**之间做出权衡。

---

### 1. 最优置换（OPT, Optimal Replacement）

- **核心思想**：置换未来最长时间内不会被使用的页面。
- **实现方式**：需预先知道进程完整的页面访问序列，选择未来引用距离最远的页面换出。
- **性质**：缺页率理论上最低，可作为其他算法的**性能上界**（基准）。
- **局限性**：无法预知未来访问模式，**仅作为理论比较标准**，实际系统中不可实现。

**示例**：访问序列 `7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1`，3个页框：

| 操作 | 页框内容 | 缺页 |
|------|----------|:----:|
| 访问7 | 7 | ✓ |
| 访问0 | 7, 0 | ✓ |
| 访问1 | 7, 0, 1 | ✓ |
| 访问2 | 2, 0, 1（置换7，因7最久未使用） | ✓ |
| 访问0 | 2, 0, 1 | ✗ |
| ... | ... | ... |

---

### 2. 最近未使用（NRU, Not Recently Used）

- **核心思想**：利用页表项的**引用位 R** 和**修改位 M** 将页面分类，优先置换最近既未被访问又未被修改的页面。
- **分类策略**（R位和M位由硬件维护）：
  - **第0类**：R=0, M=0 —— 最佳置换候选。
  - **第1类**：R=0, M=1 —— 需写回磁盘，但未被访问。
  - **第2类**：R=1, M=0 —— 可能很快会被再次访问。
  - **第3类**：R=1, M=1 —— 最差候选，可能被访问且需写回。
- **操作方式**：
  - 系统定期（如每次时钟中断）将所有页面的R位清零。
  - 缺页时，随机从**编号最低的非空类**中选择一页置换。
  - 同类别内随机选择。
- **优点**：实现简单、开销小。
- **缺点**：分类粒度粗（仅4类），性能不如LRU等算法。

---

### 3. 先进先出（FIFO, First-In First-Out）

- **核心思想**：维护一个队列，页面按进入内存的顺序排列；缺页时置换**驻留时间最长**的页面。
- **数据结构**：链表或环形缓冲区，队首是最早进入的页面，队尾是最新进入的页面。
- **缺点**：
  - 可能置换**频繁使用的**页面（如包含核心循环代码的页面）。
  - 存在 **Belady异常**：页框数增加反而导致缺页率上升。
- **示例**（Belady异常）：访问序列 `1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5`：
  - 3个页框：缺页9次。
  - 4个页框：缺页10次（更多页框反而更多缺页！）。

| 特点 | 说明 |
|------|------|
| **优点** | 实现最简单，维护成本低。 |
| **缺点** | 性能不稳定，可能置换高频页面，存在Belady异常。 |

---

### 4. 第二次机会（Second Chance）

- **核心思想**：在FIFO基础上引入引用位，给"被访问过的页面"第二次机会。
- **工作流程**：
  1. 检查队首页面（FIFO顺序）。
  2. 若 **R=0**：直接置换该页面。
  3. 若 **R=1**：将R位清零，将该页面移至**队尾**（视为新调入页面），继续检查新的队首。
- **本质**：查找R=0的页面，若所有页面的R位均为1，则退化为FIFO（遍历一圈后所有R位都被清零回到原点）。
- **优点**：比FIFO更好地保护频繁使用的页面。
- **缺点**：频繁移动页面影响效率；最坏情况下需遍历整个队列。

---

### 5. 时钟算法（Clock）

- **核心思想**：改进第二次机会算法，将页面组织成**环形链表**，维护一个指针而非移动页面。
- **工作流程**：
  1. 指针指向下一个候选页面（循环移动）。
  2. 检查当前页面的 R 位：
     - **R=0**：置换该页面，指针移向下一位。
     - **R=1**：清零 R 位，指针移向下一位，继续检查。
  3. 若遍历一圈回到原点（所有 R 位均为1），则置换当前指针指向的页面。
- **与第二次机会的区别**：无需移动链表节点，仅移动指针，效率更高。
- **Clock算法与NRU的区别**：NRU是周期性地清除R位然后随机选择；Clock是在缺页时实时检查R位，有选择性地跳过最近用过的页面。

| 特点 | 说明 |
|------|------|
| **优点** | 实现简单，效率高于Second Chance，广泛用于实际系统（如Linux）。 |
| **缺点** | 对脏页（M=1）未做优先处理。改进版可结合修改位（如 Clock-Pro）。 |

---

### 6. 最近最少使用（LRU, Least Recently Used）

- **核心思想**：置换**最长时间未被使用**的页面——基于**局部性原理**，过去未使用的页面未来也大概率不用。
- **实现方式对比**：

| 实现方式 | 原理 | 性能 | 实际应用 |
|----------|------|:----:|:--------:|
| **链表法**（硬件实现） | 每次访问页面移至链表头部，缺页时置换尾部。 | 速度快但硬件成本高 | 早期小型系统 |
| **计数器/矩阵法** | 为每个页表项维护一个时间戳或使用 n×n 矩阵记录访问顺序。 | 精确但矩阵规模随页框数平方增长 | 很少使用 |
| **老化算法（Aging）** | 软件模拟，定期（如每次时钟中断）右移引用位并累加，高位数越大表示越近被访问过。 | 近似度好、实现简单 | 实际系统常用 |

- **老化算法细节**：
  1. 每个页面维护一个 n 位计数器（如8位），初始为0。
  2. 每个时钟周期：右移所有计数器，将引用位 R 的值加到计数器最高位（或最左边）。
  3. 缺页时选择计数值最小的页面置换。
  4. 效果：近期被访问的页面计数器值更大，体现"最近使用"的优先级。
  
  **示例**（3个页面A、B、C，3位计数器）：
  
  | 时钟周期 | A的R | B的R | C的R | A计数器 | B计数器 | C计数器 |
  |:--------:|:----:|:----:|:----:|:-------:|:-------:|:-------:|
  | 0 | 1 | 0 | 1 | 100 | 000 | 100 |
  | 1 | 0 | 1 | 0 | 010 | 100 | 010 |
  | 2 | 1 | 1 | 0 | 101 | 110 | 001 |
  
  缺页时计数器最小的页面优先被置换。
  
- **与NFU（最不常用）的区别**：老化算法关注近期而非全局频率，能更好适应访问模式的变化。

| 特点 | 说明 |
|------|------|
| **优点** | 性能接近OPT，符合局部性原理，无Belady异常。 |
| **缺点** | 硬件实现成本高；软件模拟（Aging）有精度损失（历史信息随时间衰减）。 |

---

### 7. 工作集算法（Working Set）

- **工作集概念**：进程在最近 Δ 次内存访问中所引用的页面集合。Δ 称为**工作集窗口**。
- **工作集特性**：
  - 随进程执行阶段动态变化。
  - 工作集大小（WSS）不足时会导致频繁缺页（**抖动**）。
  - 操作系统应保证：**可用页框数 ≥ 所有活跃进程的 WSS 之和**。
- **核心思想**：缺页时，淘汰**不在当前工作集中**的页面。
- **实现方式**：
  - 利用页表项的引用位和上次访问时间。
  - 定期扫描所有页面：
    - 若 R=1，记录当前时间作为最后使用时间。
    - 若 R=0 且距上次使用时间 > τ（窗口阈值），则该页面不在工作集中，可置换。
    - 若 R=0 但距上次使用时间 ≤ τ，保留该页面。
- **优点**：预防抖动，保证进程性能。
- **缺点**：需定期扫描整个页表，开销大。

#### WSClock 算法（结合工作集与时钟）

- **核心设计**：结合工作集算法与Clock指针扫描，实用性强，被许多实际系统采用。
- **数据结构**：页面组织成环形链表，每个条目保存**引用位R**、**修改位M**和**最后使用时间**。
- **工作流程**：
  1. 指针沿环形链表扫描页面。
  2. 若当前页面 **R=1**：标记为"当前在工作集中"，清零 R，记录当前时间为最后使用时间，继续扫描。
  3. 若 **R=0** 且 **年龄 > τ**（不在工作集中）：
     - 若 **M=0**：直接置换。
     - 若 **M=1**：将该页调度写回磁盘（异步），继续扫描（不阻塞）。
  4. 若指针遍历一圈未找到置换页面，则：
     - 至少有一个脏页写回请求：等待写回完成，置换已干净的页面。
     - 无脏页：任选一个页面置换（退化）。
- **优点**：既考虑了页面访问的频率（工作集），又结合了Clock的高效扫描机制，**处理脏页时不阻塞扫描**。

| 特点 | 说明 |
|------|------|
| **优点** | 融合工作集的理论精确性与Clock的工程高效性，能有效防止抖动。 |
| **缺点** | 实现复杂度较高；需记录页面的最后使用时间。 |

## 六、分页系统设计问题

### 1. 局部与全局分配策略
- **局部置换**：每个进程在自己的页框集中置换。
- **全局置换**：从所有进程中回收页框。
- 可根据进程大小或优先级分配页框。

### 2. 负载控制（Load Control）
- 当系统抖动（thrashing）时，页面失效频繁。
- 解决方法：减少多道程序度，将部分进程换出到磁盘。

### 3. 页面大小选择
- 小页面优点：内部碎片少，适合数据结构和代码段。
- 小页面缺点：页表大，磁盘传输时间开销相近。
- 典型大小：4KB或8KB。

### 4. 分离指令与数据空间（I/D空间）
- 可提高空间利用率和共享效率。

### 5. 共享页面
- 多个进程可共享同一程序代码的页表（只读部分）。

### 6. 清理策略（Cleaning Policy）
- 使用**分页守护进程（paging daemon）** 定期检查内存，提前将脏页写回磁盘，保证空闲页框充足。

## 七、分页的实现问题

### 1. OS参与分页的时机
- **进程创建**：确定程序大小，创建页表，分配内存空间。
- **进程执行**：重置[MMU](#四、虚拟内存)，刷新[TLB](#4. 转换检测缓冲区（TLB, Translation Lookaside Buffers）)。
- **缺页处理**：定位虚拟地址，分配页框，读入页面，更新页表。
- **进程终止**：释放页表、页框和磁盘上的备份空间。

### 2. 缺页处理流程
1. 硬件陷入内核，保存程序计数器
2. 保存通用寄存器。
3. OS确定所需的虚拟页面。
4. 检查地址合法性，寻找空闲页框。
5. 若选中的页框为脏页，则写回磁盘。
6. 从磁盘调度读入所需页面。
7. 更新页表。
8. 回退导致缺页的指令到开始状态。
9. 调度缺页进程，恢复寄存器，继续执行。

### 3. 后备存储（Backing Store）
- (a) 静态交换区：始终在磁盘保留页面副本。
- (b) 动态备份：仅当页面被换出时才写入磁盘（无初始副本）。

## 八、分段（Segmentation）

### 1. 分段的原因
- 一维地址空间中，多个表（如编译器符号表、代码段、栈）可能相互冲突。
- 分段允许每个表独立增长或收缩。

<img src="/images/operating-system/image-20260518220144864.png" alt="image-20260518220144864" style="zoom:50%;" />

### 2. 分段的优点
- 简化动态数据结构的处理。
- 方便独立编译的模块链接。
- 便于进程间共享代码或数据。
- 不同段可设置不同的保护属性（读/写/执行）。

### 3. 分段与分页的比较
- 分段：逻辑上独立的地址空间，段大小可变。
- 分页：统一的物理页框，透明于程序员。

<img src="/images/operating-system/image-20260518220305206.png" alt="image-20260518220305206" style="zoom:50%;" />

### 4. 纯分段的实现
- 内存中会出现**棋盘状碎片（checkerboarding）**，需通过**内存紧凑**解决。

### 5. 分段与分页结合

纯粹分段会因段大小不一导致**棋盘状碎片**（需内存紧凑解决），而纯粹分页对程序员不透明、难以处理逻辑模块的独立增长。结合二者可兼得分段逻辑独立性与分页内存管理效率。

#### 基本思想 

- 用户视角：程序由多个**逻辑段**（代码段、数据段、栈段等）组成。
- 系统视角：每个段再划分为固定大小的**页**，段内地址 = 页号 + 页内偏移。
- 地址结构：`段号（Selector） | 段内页号（Page）| 页内偏移（Offset）`
- 转换过程：段号 → 描述符表 → 段基址 + 逻辑地址 → 线性地址 → 分页 → 物理地址

#### MULTICS 系统

MULTICS 是最早实现段页式结合的系统，设计目标之一是支持巨大的虚拟地址空间（2^36 字节 = 64GB）。

**地址结构**：

![image-20260518221451267](/images/operating-system/image-20260518221451267.png)

**地址转换过程**：

1. **段号 → 描述符段**：进程有一个**描述符段**（Descriptor Segment），每个描述符指向该段对应的**页表**。将段号装入描述符段基址寄存器，找到该段的描述符。

   ![image-20260518220706905.png](/images/operating-system/image-20260518220706905.png)

2. **描述符 → 页表**：描述符中包含该段页表的物理地址、段大小、保护信息。

3. **段内地址 → 物理地址**：取段内地址的高6位作为页号，查页表得到物理页框号；低10位为页内偏移。

4. **组装**：物理地址 = 页框号 × 1KB + 偏移。

**硬件加速**：
- MULTICS 使用**两级TLB**加速地址转换：
  - 一级缓存：最近使用的描述符。
  - 二级缓存：最近使用的页表条目。
- 每个进程切换时需更新描述符段基址等寄存器。

**优缺点**：

| 特点 | 说明 |
|------|------|
| **优点** | 段式编程模型清晰，支持模块化、共享和保护；分页消除外部碎片。 |
| **缺点** | 地址转换需查描述符表 + 页表，访存次数多，硬件复杂度高。 |

3. 32位线性地址

**分段地址转换（逻辑地址 → 线性地址）**：

1. **选择符（Segment Selector）** 由三部分组成：
   - **索引**（Index, 13位）：在描述符表中的位置。
   - **TI**（Table Indicator, 1位）：选择描述符表，0 = **GDT**（全局描述符表），1 = **LDT**（局部描述符表）。
   - **RPL**（Requested Privilege Level, 2位）：请求者特权级（0 ~ 3），0为最高（内核），3为最低（用户）。

2. **描述符表**：
   - **GDT（Global Descriptor Table）**：全局描述符表，存放所有进程共享的描述符（如内核段、空段）。
   - **LDT（Local Descriptor Table）**：局部描述符表，每个进程独立拥有，存放该进程私有的描述符。
   - 描述符内容：**段基址**（Base, 32位）、**段界限**（Limit, 20位）、**保护属性**（读/写/执行/特权级等）。

3. **转换公式**：
   - 从 GDTR/LDTR 寄存器获取描述符表物理地址。
   - 线性地址 = 描述符中提取的段基址 + 偏移量。
   - 检查：偏移量 ≤ 段界限（否则产生段错误）。

**分段 → 分页转换（线性地址 → 物理地址）**：

Pentium 支持两级分页（32位模式）：

<img src="/images/operating-system/image-20260518222145552.png" alt="image-20260518222145552" style="zoom:50%;" />

1. **页目录**（Page Directory）：从 CR3 寄存器获取当前进程页目录物理地址，使用线性地址高10位索引，找到对应的**页目录项（PDE）**。PDE 指向一个页表。
2. **页表**（Page Table）：用线性地址中间10位索引页目录项指向的页表，找到**页表项（PTE）**。PTE 中包含物理页框号（20位）。
3. **偏移**：线性地址低12位直接作为页内偏移。
4. **物理地址** = 页框号 × 4KB + 偏移。

**分页控制位**（PDE 和 PTE 共有）：
- **P（Present）**：页面/页表是否在内存中。
- **R/W**：读/写权限。
- **U/S**：用户/超级用户权限。
- **A（Accessed）**：是否被访问过。
- **D（Dirty）**：是否被修改过（仅 PTE 有）。

**分段与分页的协作**：

| 阶段 | 负责单元 | 输入 | 输出 |
|:----:|:---------|:-----|:-----|
| 1 | **分段单元（Segmentation Unit）** | 逻辑地址（选择符:偏移） | 线性地址 |
| 2 | **分页单元（Paging Unit）** | 线性地址 | 物理地址 |

- 分段提供**逻辑隔离**和**权限保护**：不同段对应不同特权级、不同描述符表。
- 分页提供**物理内存管理**：虚拟内存、按需调页、页面置换。
- 典型用法：**段基址设为0**，所有段共享同一线性地址空间（"平坦模式"），此时分页是实际的内存管理机构，分段仅用于保护。

**扁平模式（Flat Model）**：
现代操作系统（Linux、Windows）通常将所有段基址设为 0，界限设为 4GB，使逻辑地址 = 线性地址 = 虚拟地址。此时分段被"绕过"，实际内存管理完全依赖分页。这种做法简化了实现，同时保留了 x86 架构的硬件兼容性。

**优缺点**：

| 特点 | 说明 |
|------|------|
| **优点** | 分段提供硬件级保护（特权级、段权限）；分页支持虚拟内存；灵活支持平坦和段式两种模式。 |
| **缺点** | 地址转换路径长（段 → 页目录 → 页表），访存次数多；x86 段式设计复杂，现代 OS 多未充分利用。 |

#### 分段与分页对比总结

| 维度 | 分段 | 分页 | 段页结合 |
|:----|:-----|:-----|:---------|
| **视角** | 程序员可见 | 程序员透明 | 逻辑上分段，物理上分页 |
| **大小** | 段大小可变 | 页大小固定 | 段可变，段内页固定 |
| **碎片** | 外部碎片（棋盘状） | 内部碎片 | 内部碎片（仅在段最后一页） |
| **保护** | 段级（读/写/执行，特权级） | 页级（读/写） | 双重保护 |
| **共享** | 按段共享 | 按页共享 | 灵活 |
| **地址转换** | 基址 + 界限 | 页表/多级页表 | 段表 → 页表 |
| **典型系统** | 早期 OS | 现代 OS（Linux） | MULTICS, x86
